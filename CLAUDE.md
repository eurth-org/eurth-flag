# Building Flagwright

Flagwright is the flag maker at flag.eurth.org, one of Eurth's worldbuilding tools. It is live: `main` deploys. The standing instructions:

- **Flagwright's own design is kept exactly as it was perfected** (Stijn, 16 November 2026). The suite provides only the header and the footer. Everything between them (the flag and the Preview badge, the headline, the bar with Simple, Advanced, Random, Undo, Redo and Save, the panels, the layout tiles, the rows of colour swatches, the pills, buttons and sliders, the flag itself, and the guide, glossary and templates pages) keeps Flagwright's own styles, sizes, corners, weights, colours and Font Awesome icons, as on flag.eurth.org. Never restyle the tool to the suite's rules, and never swap its classes for `eu-` ones. A change to how the tool looks needs Stijn's word first.
- Flagwright is exempt from the suite's AAA-contrast and 44px-target checks and is held to WCAG AA with 24px targets: `"eurth": { "axe": { "level": "aa", "targets": 24 } }` in `package.json`. `tests/contrast.test.ts` checks its own colour pairs. If `npm run axe` finds something, report it; don't restyle the tool to silence it.
- How that is built: every page is `src/layouts/Base.astro`, which puts the page inside the `.fw` wrapper between the suite's header and footer. Flagwright's styles live in `src/styles/app.css` and `src/styles/site.css` and in each component, all scoped to `.fw`. Its tokens are declared on `.fw`, because several share a name with the suite's but not a value; `app.css` also undoes the suite's base styles inside the wrapper. The suite's own windows (the share dialog, the question Random asks) keep the suite's look. When something in the tool looks off, compare it with the live site before changing a style.
- Read `node_modules/@eurth/style/HANDBOOK.md` first. On everything else the tools share (stack, the shell, privacy, search, sharing, offline, launch, writing), the handbook wins over any brief; say so if they disagree. Its Shell section says a tool that was live before the suite keeps its own design.
- The shell comes from `@eurth/style` and is never rebuilt here: the header, the footer, the theme switch, the scroll line, the share dialog, the question Random asks, toasts and the offline note. Random in the maker's bar is the suite's `RandomButton`, wearing Flagwright's look. The flag palette and the emblems are the tool's data.
- Nothing is stored: no cookies, localStorage, sessionStorage or IndexedDB. A flag lives in its link (query string, versioned: `?s=1.…`, `?f=1.…`) and in the nation's profile file.
- Links are forever. Old `#s=` and `#f=` links are all over the forum and must keep opening the same flag; when the shape of a link changes, raise its version and keep reading the old ones. `tests/flag.test.ts` holds real old links.
- Flagwright owns the `flag` section of the profile file (`link`, `summary`, `svg`, `ratio`, `colours`) and leaves every other section exactly as it was.
- `eurth.config.mjs` and `@eurth/style/build` are for build time only; never import them from browser code.
- Found a bug or a gap in the shell? Don't patch around it here: it is fixed in `@eurth/style`, and every tool has it by morning.
- A feature goes into `roadmap.md` in the same commit that adds it; a point from a review goes into `docs/feedback-log.md`.
- Done means: the tool still looks and behaves as on the live site, `npm run check`, `build`, `test`, `axe` and `smoke` passing, README, roadmap and feedback log up to date.
- Ask Stijn before spending money, adding a Worker script or any Cloudflare product beyond static assets, or changing another repository.
